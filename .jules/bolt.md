## 2024-05-24 - Cached Dynamic Library and Symbol lookups for IOHIDEventSystemClient
**Learning:** If an application continuously monitors hardware state (e.g. max die temperature), reading from `IOHIDEventSystemClient` via `dlsym` and creating a new client every time is an anti-pattern. While typical of simple one-off readings, in a continuous tight loop, this repeatedly loads/resolves symbols and objects, creating unnecessary overhead. Also, when unloading dynamically loaded libraries with `dlclose` that instantiated objects, we must explicitly `nil` out those objects before calling `dlclose`, otherwise ARC may attempt to deallocate them after the `dealloc` routine has been unloaded.
**Action:** Cache `dlsym` resolved function pointers and the `IOHIDEventSystemClient` instance into class properties during `init()`. Always explicitly nil out objects obtained from dynamically loaded libraries *before* calling `dlclose` in the `deinit` block to ensure safe ARC deallocation.
