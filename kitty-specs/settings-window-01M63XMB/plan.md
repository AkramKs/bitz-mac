# Implementation Plan: Dedicated Settings Window & Streamlined Menu Bar Dropdown

**Branch**: `feat/issue-49-settings-window` | **Date**: 2026-10-29 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/kitty-specs/settings-window-01M63XMB/spec.md` (Tracks GitHub issue #49)

## Summary

Decouple mascot customization, behavior tuning, agent management, and telemetry settings from the transient macOS menu bar extra into a dedicated, standard macOS Settings window (`Settings...` menu item and `⌘,` keyboard shortcut). Streamline `BitzMenuBarContentView` into a fast, glanceable status dropdown while preserving the 100% click-through guarantee of `MascotOverlayPanel`.

## Technical Context

**Language/Version**: Swift 6.0 (swift-tools-version 6.0)  
**Primary Dependencies**: SwiftUI, AppKit (`NSWindowController`, `NSHostingController`, `MenuBarExtra`); no third-party dependencies  
**Storage**: `UserDefaults` across existing stores (`AvatarScaleStore`, `AvatarOpacityStore`, `AvatarPositionStore`, `DisplayPreferenceStore`, `TelemetrySettingsStore`, `AgentMonitorService`, `ActivityMonitorService`)  
**Testing**: XCTest in `Tests/BitzTests/` (unit tests for settings persistence, window controller behavior, and dropdown model contracts)  
**Target Platform**: macOS 14.0+, Apple Silicon  
**Project Type**: Single Swift package (`BitzCore` library + `Bitz` executable)  
**Performance Goals**: Settings window opens in < 300 ms; memory footprint remains lightweight; overlay continues running at 60 FPS  
**Constraints**: Mascot panel MUST retain `ignoresMouseEvents = true` (`C-001`); Settings window must be single-instance (`C-003`); no keyboard focus stealing from external apps (`C-002`)  
**Scale/Scope**: 1 window controller, 5 tab views under `src/Views/Settings/`, refactored `BitzMenuBarContentView` in `src/App/BitzApp.swift`, and supporting test suite  

## Charter Check

- **Click-Through Guarantee**: PASS. The settings window is an independent standard window with normal window chrome; the mascot overlay panel remains strictly non-activating with `ignoresMouseEvents = true`.
- **Zero Keyboard Focus Stealing**: PASS. The overlay panel never becomes key. Only the Settings window accepts keyboard input when explicitly opened by the user.
- **Privacy & Permissions**: PASS. Zero new permissions requested.
- **Multi-Display & Clamping**: PASS. Screen positioning preferences respect clamped visible display bounds.

## Design Decisions

1. **Window Management Strategy**:
   - Provide a dedicated `@MainActor final class SettingsWindowManager: ObservableObject` in `src/App/Settings/SettingsWindowManager.swift`.
   - Uses `NSWindowController` wrapping a SwiftUI `SettingsRootView` via `NSHostingController`.
   - Guarantees single-instance behavior: if already open, `showWindow()` calls `makeKeyAndOrderFront(nil)` and `NSApp.activate(ignoringOtherApps: true)`.
   - Handles standard macOS closing and release-on-close policies cleanly.

2. **Tabbed Settings Architecture (`SettingsRootView`)**:
   - Organized into clean macOS-style tabs with SF Symbols:
     - **General (🎨)**: Avatar size slider/stepper/presets, opacity slider/presets, corner anchor selection, drag unlock button, and multi-display routing.
     - **Behaviors (🐾)**: Work streak thresholds, break recharge cadence, custom productive & dopamine-drain application rules.
     - **AI Agents (🤖)**: Speech bubble popups toggle, monitored agents catalog checkboxes, Claude Code hooks installation and status indicator.
     - **Telemetry (📊)**: Visible metrics checkboxes, display placement toggles (HUD, bubble carousel, menu title), polling interval, and disk/CPU warning alerts.
     - **Advanced & About (🧪)**: State simulation overrides, keyboard shortcut cheat sheet, automatic update check toggle, and Launch at Login.

3. **Streamlined Menu Bar Dropdown (`BitzMenuBarContentView`)**:
   - Trim the root dropdown from 35+ items down to essential, glanceable items:
     1. Status header: Mascot state, Continuous Focus Streak, PTS score.
     2. Quick action: `Pet Bitz (<3) [P]`.
     3. Quick toggle: `Unlock/Lock Position [⎋ Esc]` (when unlocked).
     4. Active warning/event summary card: Displays disk warning, overheating, or active agent event if present.
     5. Divider.
     6. `Settings... [⌘,]` (opens the settings window).
     7. `Check for Updates...`.
     8. Divider.
     9. `Quit Bitz [⌘Q]`.

## Implementation Concern Map

### IC-01 — Settings Window Infrastructure & Single-Instance Controller
- **Purpose**: Provide a robust, single-instance macOS window controller to host SwiftUI settings tabs without affecting the floating overlay panel.
- **Relevant requirements**: FR-001, FR-003, NFR-001, C-002, C-003
- **Affected surfaces**: `src/App/Settings/SettingsWindowManager.swift`, `src/App/BitzApp.swift`
- **Sequencing/depends-on**: none
- **Risks**: Ensuring window level and focus activation don't accidentally manipulate `MascotOverlayPanel` attributes.

### IC-02 — Modular Settings Tab Views
- **Purpose**: Migrate extensive configuration controls into organized, dedicated tabs.
- **Relevant requirements**: FR-004, FR-005, FR-006, FR-007, FR-008, NFR-002, NFR-004
- **Affected surfaces**: `src/Views/Settings/*`
- **Sequencing/depends-on**: IC-01
- **Risks**: Live binding to multiple `@ObservedObject` / `@EnvironmentObject` stores without UI refresh glitches.

### IC-03 — Streamlined Menu Bar Dropdown
- **Purpose**: Refactor `BitzMenuBarContentView` down to an ultra-clean, glanceable popover.
- **Relevant requirements**: FR-002, FR-003, NFR-003
- **Affected surfaces**: `src/App/BitzApp.swift`
- **Sequencing/depends-on**: IC-01, IC-02
- **Risks**: Retaining essential quick actions (Pet Bitz, Lock Position, active warnings) while removing submenus.

- **Sequencing/depends-on**: IC-01, IC-02, IC-03
